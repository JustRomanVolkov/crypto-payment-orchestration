# Глоссарий Billing

[Billing](../README.md) → Справочник

| Термин | Значение в этой документации |
|---|---|
| Billing | Контекст, который ведёт Payment, выбирает PSP и принимает решение о факте оплаты; предмет и результат покупки находятся в модуле продукта. |
| Purchase / `purchase_id` | Бизнес-намерение купить продукт на сохранённых условиях и его стабильный идентификатор. |
| Payment | Одна логическая оплата покупки; сохраняется при смене провайдера. |
| Агрегат Payment | Граница согласованности Payment: корень управляет попытками и переходами; история входящих наблюдений хранится отдельно. |
| PaymentAttempt | Обращение к конкретному PSP в рамках Payment, включая подготовку, создание счёта и его исход. |
| PSP | Внешний платёжный провайдер, выдающий реквизиты и сведения о переводах. |
| Merchant account | Аккаунт и договорный допуск конкретного бизнеса к услугам PSP. Публичная поддержка категории его не заменяет. |
| Счёт / invoice | Реквизиты или платёжная страница, по которым покупатель может отправить средства. Название endpoint конкретного PSP может отличаться. |
| Маршрут / route snapshot | Сохранённый для Payment порядок записей `(PSP, merchant account, environment, версия конфигурации)` и версия политики; текущий допуск проверяется перед каждым новым create. |
| Политика маршрутизации | Правило упорядочивания допущенных PSP. Не является контрактом провайдера или разрешением на переключение. |
| Допуск / eligibility | Проверка бизнес-разрешения и совместимости PSP с активом, сетью, суммой и другими условиями платежа. |
| Каскад / fallback | Переход к следующему PSP для той же логической оплаты после безопасного исхода предыдущей попытки. |
| Неизвестный исход создания | Внешний запрос мог создать счёт, но достоверного ответа нет. Timeout и отсутствие webhook не равны отказу. |
| Наблюдение / observation | Полученное от PSP сообщение или ответ с источником, временем, статусом и денежными полями; ещё не решение Billing об оплате. |
| Сверка / reconciliation | Получение и сопоставление внешних сведений с сохранённым Payment, особенно после неизвестного исхода или пропущенного уведомления. |
| Use case / flow | Use case — входная операция application; flow — последовательность её выполнения с участием других операций, worker и PSP. |
| Protocol / адаптер | Python-интерфейс зависимостей Billing на основе `typing.Protocol` и его инфраструктурная реализация. В архитектуре такой интерфейс также называют портом. |
| Котировка / quote | Зафиксированные для попытки условия пересчёта цены и сумма, которую должен внести покупатель. |
| Фактическая оплата и выплата | Сумма, отправленная покупателем, и сумма, доставшаяся merchant после комиссий и конвертации; для проверки достаточности это разные величины. |
| Подтверждённая оплата | Денежное решение Billing после проверки привязки, суммы, актива и сети; статус PSP сам по себе его не заменяет. |
| Выдача / fulfillment | Однократное предоставление оплаченного продукта модулем продукта; может выполняться в общей транзакции или после надёжной доставки факта оплаты. |
| Grant | Сохранённый модулем продукта результат покупки, например право доступа; уникален по `(tenant_id, purchase_id)`. Не означает завершённую генерацию или доставку медиа. |
| БД / схема / кластер PostgreSQL | Схема разделяет объекты и права внутри БД; соединение работает с одной БД. Несколько БД одного кластера делят ресурсы, WAL и границу физического восстановления. |
| Unit of Work / UoW | Управление одной локальной SQL-транзакцией. Общий commit модулей требует общего соединения; одинаковая БД или объект Session с разными Engine этого не гарантируют. |
| Outbox | Обязательство передать факт принятой оплаты, сохраняемое Billing атомарно с `PAID`, когда выдача имеет отдельный commit. |
| Inbox | Записи принятого входа и обработки у получателя. `provider_observations` хранит наблюдения PSP в Billing; inbox модуля продукта защищает применение доставленного факта оплаты. |
| Relay | Исполнитель доставки из outbox: передаёт событие с постоянным ID и сохраняет подтверждение получателя; повторы допустимы. |
| Claim / lease | Сохранённое право исполнителя на работу и его ограниченный срок. Истечение не отменяет уже отправленный запрос PSP и не разрешает повторный create. |
| Backlog / due work | Незавершённая работа и её часть с наступившим сроком исполнения. Возраст готовой работы считают от исходного срока, а не от последней публикации в Redis. |
| SLO / p99 | Целевая характеристика обслуживания / значение, в которое укладывается 99% измерений. Числа в расчёте мощности — предлагаемые бюджеты испытаний до их согласования. |
| PITR | Восстановление PostgreSQL на выбранный момент по резервной копии и WAL. Для общей инфраструктуры нужно учитывать границу кластера и последующую сверку внешних денежных фактов. |

Термины конкретного API, включая `payment_id` NOWPayments, определены в [документе интеграции](../architecture/providers/nowpayments.md).
