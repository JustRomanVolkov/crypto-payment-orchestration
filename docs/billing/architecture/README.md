# Архитектура Billing

[Billing](../README.md) → Архитектура

Здесь описаны граница Billing, правила платежа, хранение и обработка. Выбор размещения приложения и БД и переход между вариантами описаны в [развитии Billing](../roadmap/README.md).

## Как связаны разделы

Billing — ограниченный контекст. В его домене [агрегат Payment](domain/payment.md) защищает согласованность одной оплаты, а [политика маршрутизации](routing/policy.md) формирует порядок допустимых PSP; [каскад](routing/cascade.md) задаёт правило безопасного перехода между попытками. [Use cases application](contracts/application.md) принимают команды и координируют доменные решения через интерфейсы зависимостей. Документы в `flows/` показывают, как эти операции разворачиваются во времени с участием worker и PSP. [Адаптеры](contracts/provider-adapter.md) реализуют интерфейсы; размещение классов показано в [структуре кода](code-structure.md).
